## 摘要

C/C++程序中的缓冲区越界等空间内存错误可能造成数据破坏、程序崩溃甚至控制流劫持。Arm Memory Tagging Extension（MTE）通过比较指针标签与内存标签检测非法访问，但传统方案通常随机分配标签。在MTE仅提供4位标签的情况下，相邻对象可能获得相同标签，攻击者也可能通过重复尝试或侧信道获取标签信息，因此随机标签主要提供概率性保护。

StickyTags将标签从一次性的随机属性改为与内存空间位置绑定的持久属性。该方法按对象尺寸类别组织堆和栈区域，使连续对象槽采用确定性的16标签轮转，从而在标签周期限定的范围内为跨对象访问提供确定性保护。同时，持久标签避免在每次分配和释放时反复标记内存，有利于降低运行开销。

本实验基于论文作者公开的StickyTags修改版LLVM/SafeStack和TCMalloc，在Windows 11、WSL2和QEMU AArch64 MTE环境中完成机制级初步复现。实验自行设计了堆栈越界功能测试、标签轮转测试、边界距离测试、标签持久性测试、MTE粒度测试和保护版/未保护版对照测试。结果显示：20轮功能对照中，未保护版堆、栈越界均未产生MTE故障，保护版堆、栈越界均以100%的比例产生MTE专用故障；保护版860条机制测试全部通过，680个预期MTE故障全部被观察到，未出现普通段错误被误计为MTE故障的情况；10000次持久性迭代中发生9990次地址复用，未观察到标签变化。上述结果支持StickyTags确定性标签轮转、有限距离空间保护、标签持久性以及堆栈覆盖等核心设计。本实验未复现真实Arm设备性能、SPEC、Juliet、真实CVE和侧信道实验，因此结果只支持功能与机制层面的初步复现结论。

## 1. 实验背景

### 1.1 空间内存错误

C和C++允许程序直接操作指针和内存，这种灵活性也带来了空间内存安全问题。当程序使用一个对象的指针访问对象边界之外的地址时，就会产生空间越界。常见形式包括栈缓冲区溢出、堆缓冲区溢出、越界读、越界写以及由类型混淆引起的跨对象访问。

越界访问的影响取决于目标位置和访问方式。越界读可能泄露敏感数据，越界写可能破坏相邻对象、函数指针或控制数据。传统边界检查能够提供较完整的保护，但通常需要在大量内存访问前插入检查，可能带来较高的运行开销。因而，如何在保护能力和运行开销之间取得平衡，是内存安全研究的重要问题。

### 1.2 Arm MTE基本原理

Arm MTE为指针和内存分配标签。指针高位保存逻辑标签，内存以16字节为粒度保存分配标签。程序执行内存访问时，处理器比较两者：

```text
指针逻辑标签 == 内存分配标签：允许访问
指针逻辑标签 != 内存分配标签：产生MTE标签检查故障
```

在64位AArch64系统中，MTE逻辑标签通常位于指针高字节中的4位，因此最多有16个标签值。MTE可以通过同步或异步模式报告故障。本实验采用异步模式，Linux将标签检查错误报告为`SEGV_MTEAERR`；测试程序也兼容同步模式的`SEGV_MTESERR`。

### 1.3 传统随机标签方案的不足

传统MTE方案通常在对象分配时随机选择标签，并在对象释放时重新标记内存。随机标签使攻击者难以直接预测目标对象标签，但其保护具有以下限制：

1. MTE只有4位标签，标签空间较小；
2. 相邻对象可能随机获得相同标签；
3. 当源对象和目标对象标签相同时，跨对象访问不会触发标签检查故障；
4. 攻击者可能通过重复尝试、暴力猜测或推测执行侧信道寻找匹配标签；
5. 反复进行内存标记可能造成额外运行开销。

因此，随机标签的空间错误检测通常只能给出概率保证，而不能保证附近对象一定使用不同标签。

### 1.4 StickyTags的研究目标

StickyTags关注有界空间内存错误。它不依赖标签保密，而是把标签设计为空间布局的一部分：即使攻击者知道全部标签，也无法使用当前对象的带标签指针访问标签周期内的其他对象槽。该方法的目标是在较低开销下形成较大的确定性空间保护范围，并通过持久标签减少重复内存标记。

## 2. StickyTags核心设计

### 2.1 按尺寸类别组织内存

StickyTags按size class组织对象。一个区域中的槽位保存相同尺寸类别的对象，因此连续对象槽之间的距离是固定的。假设对象尺寸类别为`S`，连续槽位的地址间隔也是`S`。固定间距使实现可以根据区域基址、对象地址和尺寸类别计算标签，而不需要为每个对象单独保存随机标签元数据。

堆对象由修改版TCMalloc管理。栈对象则由修改版LLVM SafeStack分析和组织：需要保护的对象被放入按尺寸类别划分的unsafe stack区域，并使用对应标签。

### 2.2 确定性16标签轮转

同一尺寸类别区域中的对象槽使用确定性的16标签周期。可将其抽象为：

```text
槽位：  1  2  3  4  ...  15  16  17  18
标签：  0  1  2  3  ...  14  15   0   1
```

对于任意一个对象槽，距离它1至15个槽位的对象具有不同标签。因此，从当前对象跨入这些槽位时，原指针标签与目标内存标签不匹配，MTE会产生故障。第16个槽位重新使用相同标签，因此保护范围是有限的。在相同尺寸类别中，单方向可表达的保证范围为：

```text
15 × size_class 字节
```

例如，16字节尺寸类别对应240字节的单方向保护距离；尺寸类别越大，标签周期形成的字节保护范围也越大。

### 2.3 标签持久性

StickyTags中的“sticky”表示标签与槽位空间位置保持稳定关系。对象被释放后，相同地址再次用于同一尺寸类别对象时，内存标签不需要重新随机选择。持久标签具有两个作用：

1. 维持确定性的空间布局，使附近对象的标签关系不受分配历史影响；
2. 减少每次分配、释放时重新标记内存产生的开销。

标签持久性不能解释为use-after-free保护。相反，旧指针可能继续匹配被复用槽位的标签。论文默认StickyTags把全部标签资源用于空间保护，并没有把时间错误作为核心保护目标。

### 2.4 堆保护

修改版TCMalloc利用已有的尺寸类别组织堆对象，并使相邻槽位遵循确定性标签轮转。堆分配返回的指针携带逻辑标签；对象所在内存带有分配标签。当带标签指针越界进入标签不同的附近槽位时，MTE检测到不匹配并产生故障。

### 2.5 栈保护

修改版LLVM SafeStack负责栈对象保护。编译器分析需要放入unsafe stack的对象，为不同尺寸类别建立栈区域，并在生成代码时为指针应用标签。由于栈帧会被重复进入和退出，持久标签可以避免递归或重复函数调用过程中频繁重新标记相同栈区域。

### 2.6 相较传统方法的优势与限制

| 对比项 | 传统随机标签 | StickyTags |
|---|---|---|
| 标签生成 | 分配时随机选择 | 根据对象槽位置确定 |
| 保护性质 | 概率性 | 标签周期范围内确定性 |
| 相邻对象标签 | 可能随机相同 | 前15个相邻槽位不同 |
| 标签是否依赖保密 | 通常依赖攻击者难以猜中 | 不依赖标签保密 |
| 内存重新标记 | 分配和释放时可能重复进行 | 首次初始化后保持持久 |
| 主要目标 | 概率检测空间或时间错误 | 有界空间错误保护 |

StickyTags仍然存在边界：第16个槽位开始标签重复；MTE的16字节粒度可能无法检测落入对象填充区的小越界；未标记的兼容代码和特殊栈操作可能带来兼容性问题；默认设计不提供确定性的时间安全。

### 5.2 MTE运行配置与故障判定

**启用MTE。** 机制测试程序允许进程使用带标签地址，并请求异步MTE故障模式。代码设置的标签掩码包含全部16个标签值：

```c
static void configure_mte_fault_mode(void) {
    unsigned long control = PR_TAGGED_ADDR_ENABLE | PR_MTE_TCF_ASYNC |
                            (0xffffUL << PR_MTE_TAG_SHIFT);
    (void)prctl(PR_SET_TAGGED_ADDR_CTRL, control, 0, 0, 0);
}
```

当前机制测试没有检查`prctl`的返回值。实验在正式测试前另外运行环境探针，已经观察到`HWCAP2_MTE=yes`、`mmap(PROT_MTE)`成功和`PR_SET_TAGGED_ADDR_CTRL`成功；后续日志也实际记录到MTE专用故障。因此本次结果建立在MTE环境已经单独验证的前提上，但测试程序本身仍缺少配置失败检查。

**区分MTE故障和普通段错误。** 仅观察程序以139退出并不能证明StickyTags检测成功，因为普通非法地址也可能导致`SIGSEGV`。测试程序读取`siginfo_t.si_code`并输出故障类型：

```c
const char *kind = "other SIGSEGV";
if (info->si_code == SEGV_MTEAERR) {
    kind = "SEGV_MTEAERR (asynchronous MTE tag check fault)";
}
if (info->si_code == SEGV_MTESERR) {
    kind = "SEGV_MTESERR (synchronous MTE tag check fault)";
}
```

异步模式下预期获得`SEGV_MTEAERR`和`si_code=8`。普通段错误会被单独标记为`unexpected_sigsegv`，不能计入MTE故障数。

### 5.3 堆、栈越界功能测试

**堆越界测试。** 堆测试分配两个32字节对象。正常模式只访问`first[0]`和`first[31]`；越界模式写入`first[32]`：

```c
volatile unsigned char *first = malloc(32);
volatile unsigned char *second = malloc(32);

first[0] = 0x11;
first[31] = 0x22;

if (overflow) {
    first[32] = 0x33;
}
```

保护版程序中的两个对象由修改版TCMalloc管理。`first[32]`跨入相邻对象槽后，源指针标签与目标槽标签不同，预期产生MTE故障。对照版执行同一源码但没有StickyTags标签布局，预期不会产生MTE标签故障。

**栈越界测试。** 功能程序声明两个32字节栈数组。正常模式访问`first[31]`，越界模式执行`second[32]`：

```c
if (index < sizeof(first)) {
    first[index] = 0x55;
} else {
    second[index] = 0x55;
}
```

`second[32]`在C语言对象边界上一定属于越界访问。当前功能程序没有在运行时排序地址或验证两个数组是否严格相邻；代表性日志显示本次保护版运行中两个数组的原始地址相差32字节，因此该次访问进入了相邻对象。机制测试中的栈边界用例会另外排序对象并验证连续布局，其证据比这一基础功能用例更严格。

### 5.4 StickyTags核心机制测试

**提取指针标签和原始地址。** 为了观察标签规律，机制测试分别提取指针的逻辑标签和去掉高字节标签后的原始地址：

```c
#define ADDRESS_MASK 0x00ffffffffffffffULL

static unsigned pointer_tag(const void *pointer) {
    return (unsigned)(((uintptr_t)pointer >> 56) & 0x0f);
}

static uintptr_t raw_address(const void *pointer) {
    return ((uintptr_t)pointer) & ADDRESS_MASK;
}
```

`pointer_tag`用于检查标签周期，`raw_address`用于比较对象实际地址、排序对象和确认相邻关系。

**标签轮转。** 机制程序分配并按原始地址排序32个对象，检查三个条件：前16个标签是否互不相同、相邻对象标签是否不同、相隔16槽的对象标签是否重复：

```c
int pass = count >= 32 && unique_first16 == 16 &&
           adjacent_diff == count - 1 && repeat16 == 16 && exact_stride;
```

其中`exact_stride`确认对象之间的地址差等于尺寸类别，避免在非连续布局上错误推断标签周期。

**边界距离。** 边界测试选择一段连续对象，把起始对象的带标签指针重新组合到第`slot`个目标槽原始地址，然后执行访问：

```c
volatile unsigned char *attack =
    retagged_pointer((const void *)objects[start].ptr,
                     objects[start + slot].raw);
int expected_fault = objects[start].tag != objects[start + slot].tag;
attack[0] = 0x5a;
```

当目标槽标签不同，预期产生MTE故障；第16槽标签与起始槽重复，预期访问不产生标签故障。该测试直接验证有限距离空间保护边界。

**标签持久性。** 持久性测试记录原始地址与第一次观察到的标签。相同地址再次出现时比较标签：

```c
if (state->raw[i] == raw) {
    ++state->reuses;
    if (state->tag[i] != tag) {
        ++state->mismatches;
    }
    return;
}
```

测试只有在地址确实发生复用且标签不一致次数为0时才通过。这避免了“没有地址复用所以没有标签变化”的无效结论。程序最多保存64个不同地址，但当前源码没有单独记录地址表容量不足；本次每个持久性用例只观察到1个不同地址，因此这一限制没有影响现有结果。

**MTE粒度。** 粒度测试使用逻辑大小为10字节、实际槽大小为16字节的对象，分别访问下标9、10、15、16和32。测试根据`index / 16`计算目标槽：

```c
int target_slot = index / 16;
uintptr_t target_raw = objects[start].raw + (uintptr_t)index;
```

下标10和15虽然超过逻辑对象长度，但仍位于同一个16字节MTE粒度内，预期不产生标签故障；下标16和32进入其他槽，预期发生故障。该实验验证的是MTE底层粒度限制，不能单独表述为StickyTags创新。

### 5.5 自动运行与结果判断

Shell运行器为单个用例设置超时，并从程序输出中提取退出状态、故障类型和`si_code`。机制测试对预期发生故障和预期正常退出的用例分别判断：

```bash
if [[ $expected_fault -eq 1 && $mte_fault -eq 1 &&
      $unexpected_sigsegv -eq 0 ]]; then
    pass=1
elif [[ $expected_fault -eq 0 && $mte_fault -eq 0 &&
        $unexpected_sigsegv -eq 0 && $status -eq 0 ]]; then
    pass=1
else
    pass=0
fi
```

因此，保护版没有产生预期MTE故障、预期正常的访问异常退出、出现普通段错误或用例超时都会使机制测试失败。完整机制对照还会把对照版无法形成连续布局的记录标记为跳过，而不是通过或失败。基础功能比较脚本主要负责记录和汇总故障次数，并会拒绝普通段错误；其当前版本没有自动断言必须得到0%或100%，最终比例仍需根据汇总结果解释。

## 6. 实验方案与步骤

### 6.1 测试用例与控制条件

本实验使用自行编写的C程序构造正常访问、堆越界和栈越界，并通过改变对象位置、对象尺寸、目标槽位、访问下标和重复次数形成测试组合。

| 测试条件 | 设置 |
|---|---|
| 程序版本 | StickyTags保护版、未启用StickyTags的对照版 |
| 对象位置 | 堆、栈 |
| 对象尺寸 | 10、16、32、64、128、256字节 |
| 越界位置 | 指定对象槽位或访问下标 |
| 重复次数 | 功能对照20轮、边界距离5轮、MTE粒度20轮、持久性1000次 |
| 保持一致的条件 | C测试源码、QEMU虚拟机、MTE模式、对象尺寸和访问位置 |

保护版与对照版使用相同的测试源码和运行环境。保护版启用论文修改版SafeStack并链接修改版TCMalloc，对照版不加载上述保护组件；当前构建脚本还存在保护版使用`-O2`和全程序链接优化、对照版使用`-O0`的编译选项差异。

### 6.2 实验总体步骤

实验按以下顺序进行：

1. 启动QEMU AArch64 MTE虚拟机并确认运行环境可用；
2. 将功能测试和机制测试分别编译为保护版与对照版；
3. 在虚拟机中运行正常访问、论文作者布局探针、堆越界和栈越界；
4. 重复运行保护版与对照版的基础功能测试；
5. 运行标签轮转、边界距离、标签持久性和MTE粒度测试；
6. 根据退出状态和故障类型判断结果，并保存原始日志和汇总数据。

### 6.3 基础功能与重复对照方案

基础功能测试首先检查合法访问是否能够正常完成，再分别构造堆、栈跨对象越界。两种程序的预期行为如下：

| 用例 | 保护版预期 | 对照版预期 |
|---|---|---|
| 正常访问 | 状态0，不产生MTE故障 | 状态0，不产生MTE故障 |
| 堆越界 | 状态139，产生MTE故障 | 不产生MTE标签故障 |
| 栈越界 | 状态139，产生MTE故障 | 不产生MTE标签故障 |

论文作者提供的`test/test.c`单独用于输出堆、栈地址和标签。该程序按源码主动返回1，不执行越界，因此其退出状态1不表示实验失败，也不参与两种程序的越界比较。

重复对照在保护版和对照版中各运行一次正常访问，再对堆、栈越界分别重复20轮，共形成82条记录：

```text
2条正常访问 + 2种越界 × 2个版本 × 20轮 = 82条
```

20轮重复用于检查相同受控越界行为是否稳定，统计的是MTE故障出现次数和出现比例，不用于估计现实程序中的总体漏洞检测率。

### 6.4 核心机制测试矩阵

核心机制测试的参数设置为：边界距离每个槽位重复5轮，MTE粒度每个访问下标重复20轮，标签持久性每种对象尺寸执行1000次。保护版共生成860条结果记录：

| 测试内容 | 记录数 | 构成 |
|---|---:|---|
| 标签轮转 | 10 | 堆/栈 × 5种尺寸 |
| 标签持久性 | 10 | 堆/栈 × 5种尺寸，每条内部执行1000次 |
| 边界距离 | 640 | 堆/栈 × 4种尺寸 × 16个槽位 × 5轮 |
| MTE粒度 | 200 | 堆/栈 × 5个访问下标 × 20轮 |
| 合计 | 860 | 上述记录之和 |

标签轮转和持久性使用16、32、64、128和256字节对象；边界距离使用16、32、64和128字节对象；MTE粒度测试使用10字节逻辑对象，并访问下标9、10、15、16和32。

### 6.5 完整机制对照方案

为比较是否启用StickyTags时的行为差异，同一套机制测试分别用于保护版和对照版：

```text
保护版：860条
对照版：860条
合计：1720条
```

部分对照版用例无法获得边界和粒度测试所需的连续对象布局，因此不参与对应的距离比较，也不计作成功或失败。这样可以避免把测试前提不成立的记录误认为StickyTags保护结果。

### 6.6 结果判定标准

实验结果按照以下标准判断：

- 正常访问：状态0，不产生MTE故障；
- 保护版跨标签越界：状态139，并出现`SEGV_MTEAERR`或`SEGV_MTESERR`；
- 对照版越界：不产生MTE标签故障；
- 标签轮转：前16个对象使用不同标签，相邻标签不同，相隔16个槽位后标签重复，并且对象步长正确；
- 边界距离：第1至15个目标槽位产生MTE故障，第16个槽位不产生故障；
- 标签持久性：地址发生复用，并且相同原始地址再次出现时标签保持不变；
- MTE粒度：同一16字节标签槽内不产生标签故障，跨槽访问产生MTE故障；
- 普通`SIGSEGV`、测试超时或其他异常退出不能计作MTE检测成功；
- 无法满足连续布局条件的记录不参与对应机制的成功或失败判断。

## 7. 实验结果

### 7.1 论文作者布局探针

论文作者提供的`test/test.c`只分配堆对象、声明栈对象并打印指针。一次代表性输出如下：

```text
ptr0 0xad1417024000 ptr1 0x100ad1417024030 ptr2 0x200ad1417024060
buf16 0xf00ad14167fffc0 buf15 0xe00ad14167fff80 buf14 0xf00ad1416ffff80
```

三个堆指针的原始地址依次相差48字节，其中后两个指针的高位分别携带标签1和2；栈指针也出现了标签15和14。该输出说明修改版工具链和分配器能够生成带标签的堆、栈指针。由于该程序没有执行越界访问并且固定返回1，因此这里仅将它作为地址与标签布局的观察结果，不用于判断保护效果。

### 7.2 基础功能测试结果

正常访问用例对32字节堆、栈对象执行边界内读写，程序以状态0退出，未观察到MTE故障。这说明在当前测试范围内，启用StickyTags没有阻止合法访问。

保护版堆越界用例的代表性输出为：

```text
heap first=0x400c1159a01c080 tag=4 second=0x500c1159a01c0a0 tag=5
about to write first[32] (one byte beyond the 32-byte object)
caught SIGSEGV: si_code=8 kind=SEGV_MTEAERR (asynchronous MTE tag check fault) si_addr=(nil)
EXIT_STATUS=139
```

两个对象的原始地址相差32字节，标签分别为4和5。`first[32]`越过第一个对象并进入相邻对象所在位置，但访问指针仍携带标签4，与目标位置的标签5不一致，随后产生`SEGV_MTEAERR`。退出状态139等于`128 + SIGSEGV(11)`，结合`si_code=8`可以确认这是异步MTE标签检查故障，而不是仅凭程序崩溃作出的判断。

保护版栈越界用例观察到相同类型的结果：

```text
stack first=0xf00c82182ffffe0 tag=15 second=0xe00c82182ffffc0 tag=14 index=32
about to write second[32] into the adjacent first object
caught SIGSEGV: si_code=8 kind=SEGV_MTEAERR (asynchronous MTE tag check fault) si_addr=(nil)
EXIT_STATUS=139
```

两个32字节栈对象标签分别为15和14，向低地址对象之后写入一个字节时发生标签不匹配。基础功能测试由此观察到：正常访问不产生故障，而受控的堆、栈跨对象越界均产生MTE专用故障。

### 7.3 保护版与对照版功能比较

相同功能测试源码分别编译为保护版和对照版。正常访问各执行1次，堆、栈越界各重复20次，结果如下。

| 保护版 | 正常访问 | 1 | 0 | 0.0% |
| 对照版 | 堆越界 | 20 | 0 | 0.0% |
| 保护版 | 堆越界 | 20 | 20 | 100.0% |
| 对照版 | 栈越界 | 20 | 0 | 0.0% |
| 保护版 | 栈越界 | 20 | 20 | 100.0% |

两种程序都能正常完成合法访问。保护版的40次越界均出现MTE故障，对照版的40次相同越界没有出现MTE标签故障。这里的0%和100%只表示这些受控用例中的故障出现比例，不表示现实程序中所有空间漏洞的总体检测率。对照版的0%也不表示越界没有发生，而是表示越界未被MTE标签检查报告。

### 7.5 标签轮转结果

标签轮转测试分别对堆和栈中的16、32、64、128、256字节对象进行检查。每个用例分配32个连续对象，代表性记录为：

```text
RESULT,suite=cycle,kind=heap,size=16,objects=32,
unique_first16=16,adjacent_diff=31,repeat16=16,stride_ok=1,pass=1
```

`stride_ok=1`说明32个对象按照对应尺寸连续排列；`unique_first16=16`说明前16个对象出现16种不同标签；`adjacent_diff=31`说明31组相邻对象的标签均不同；`repeat16=16`说明后16个对象分别重复前16个对象的标签。堆、栈共10条记录均得到相同结构指标，共检查320个对象。这些指标共同表明标签按照16个值形成确定性轮转，而不是仅观察到若干非零标签。

### 7.6 边界距离结果

边界距离测试覆盖堆和栈、16至128字节的4种对象尺寸、目标槽位1至16，并对每个组合重复5次。两条代表性记录如下：

```text
RESULT,suite=boundary,kind=heap,size=16,slot=1,trial=1,
expected_fault=1,exit_status=139,mte_fault=1,
fault_kind=SEGV_MTEAERR,fault_si_code=8,unexpected_sigsegv=0,pass=1

RESULT,suite=boundary,kind=heap,size=16,slot=16,trial=1,
expected_fault=0,exit_status=0,mte_fault=0,
fault_kind=none,fault_si_code=NA,unexpected_sigsegv=0,pass=1
```

第1至15个目标槽位的标签与起始对象不同，`4 × 2 × 15 × 5 = 600`次访问全部观察到MTE故障。第16个槽位因标签完成一轮循环而重新与起始标签相同，`4 × 2 × 1 × 5 = 40`次访问均正常退出。该结果说明StickyTags能够稳定检测本实验中跨越1至15个对象槽的越界，同时也实际观察到了第16槽标签回绕所形成的保护边界。

### 7.7 标签持久性结果

持久性测试覆盖堆、栈和5种对象尺寸。每种组合执行1000次分配或栈对象创建，一条16字节堆对象记录为：

```text
RESULT,suite=persistence,kind=heap,size=16,iterations=1000,
unique_addresses=1,reuses=999,mismatches=0,pass=1
```

10条记录合计执行10000次，观察到9990次相同原始地址复用，标签不一致次数为0。每个用例均只观察到1个不同原始地址，因此程序的64地址记录容量没有影响本次结果。由于测试确实观察到了地址复用，“标签不变化”不是没有复用造成的空结果。结合保护版的16标签轮转结果，这说明被重复使用的内存位置保持原有标签。

该结果只验证标签与内存位置之间的持久关系，不能单独解释为use-after-free保护。对照版所有指针标签均为0，也会得到“不变化”的表面结果，因此持久性必须与保护版的标签轮转结果结合解释。

### 7.8 MTE粒度结果

粒度测试使用逻辑长度为10字节、实际占用一个16字节标签槽的对象，分别访问下标9、10、15、16和32。

| 访问下标 | 访问位置 | 预期MTE故障 | 实际结果 |
|---:|---|---:|---|
| 9 | 10字节对象内部 | 否 | 正常退出 |
| 10 | 逻辑越界，但仍在同一16字节槽内 | 否 | 正常退出 |
| 15 | 逻辑越界，但仍在同一16字节槽内 | 否 | 正常退出 |
| 16 | 进入下一个标签槽 | 是 | `SEGV_MTEAERR` |
| 32 | 进入后续标签槽 | 是 | `SEGV_MTEAERR` |

例如，下标15的记录为`exit_status=0,mte_fault=0`，下标16则为`exit_status=139,mte_fault=1,fault_si_code=8`。每个下标在堆、栈中各重复20次，共形成200条记录：同一标签槽内的120次访问没有产生MTE故障，跨槽的80次访问全部产生MTE故障。该结果说明MTE以16字节为标签粒度，因此不能检测仍处于同一粒度内的所有逻辑越界，这也是StickyTags继承的底层限制。

### 7.9 完整机制对照结果

完整对照使用相同机制测试源码，保护版和对照版各生成860条记录。关键差异如下：

| 观察指标 | 对照版 | 保护版 |
|---|---:|---:|
| 实际MTE故障 | 0 | 680 |
| 标签轮转机制符合记录 | 0 | 10 |
| 非预期普通段错误 | 0 | 0 |
| 因连续布局条件不满足而排除的记录 | 400 | 0 |

保护版形成了前述16标签轮转，并在预期跨标签访问中产生680次MTE故障；对照版既没有形成该轮转，也没有产生MTE标签故障。对照版有400条记录无法满足测试所需的连续对象布局，其中包括320条堆边界记录和80条粒度记录。这些记录被排除，而不是计作保护成功或失败，因为普通分配器并不保证StickyTags使用的尺寸分类连续布局。

完整对照说明，启用论文修改版SafeStack和TCMalloc的程序形成了预期标签布局，而未启用这些组件的程序没有形成同样布局。由于两种程序的编译优化选项也不同，该对照能够支持保护配置与观察结果之间的关联，但不是严格的单变量实验。持久性指标没有单独用于区分两种程序，因为对照版的零标签同样不会变化。

## 8. 结果分析与讨论

### 8.1 核心标签布局分析

标签轮转测试覆盖堆、栈以及16、32、64、128和256字节五种对象尺寸。10组测试中，对象地址步长均与对应尺寸类别一致；每组前16个连续对象使用16种不同标签，全部相邻对象标签不同，后16个对象分别重复前16个对象的标签。实验结果与StickyTags按照对象槽位置进行16标签循环分配的设计一致。

论文作者提供的布局探针能够输出带标签的堆、栈指针，但只观察若干对象还不足以确定完整标签规律。本实验通过32个连续对象检查标签唯一性、相邻差异和相隔16槽重复关系，进一步验证了标签与对象空间位置之间的确定性对应关系。堆测试由修改版TCMalloc完成对象分配，栈测试由修改版SafeStack组织局部对象，两类测试得到一致结果，表明核心标签布局同时作用于堆和栈。

标签持久性测试共执行10000次对象创建或分配，其中发生9990次相同原始地址复用，未观察到标签变化。标签轮转结果表明保护版并非统一使用零标签，持久性结果则表明被复用位置的标签没有随对象生命周期重新随机改变。两项结果结合后，体现了StickyTags将标签与内存位置稳定绑定的设计。

### 8.2 空间越界保护效果分析

边界距离测试将带有起始对象标签的指针依次访问第1至16个目标槽。第1至15槽共600次访问全部产生MTE标签检查故障，第16槽共40次访问均未产生标签故障。该现象与16标签循环直接对应：前15个目标槽与起始对象标签不同，第16槽完成一个标签周期后重新使用相同标签。因此，在本实验覆盖的尺寸类别中，StickyTags形成了单方向15倍尺寸类别的确定性保护距离，同时也表现出标签周期造成的有限保护边界。

基础功能测试进一步验证了普通越界场景。保护版的堆越界和栈越界各运行20次，40次访问均产生`SEGV_MTEAERR`；正常访问未产生故障。故障判断同时使用退出状态和`siginfo_t.si_code`，因此普通段错误没有被计入MTE检测结果。该结果表明，在当前对象布局下，修改版TCMalloc和SafeStack设置的标签能够使跨对象访问触发MTE检查。

MTE粒度测试显示，10字节对象的下标10和15虽然已经超出C语言对象边界，但仍处于同一个16字节标签槽内，因此未产生标签故障；下标16和32跨入其他标签槽后产生故障。该结果反映了StickyTags依赖MTE硬件粒度所带来的限制：其保护单位是16字节标签槽，而不是每个字节的精确对象边界。

### 8.3 对照结果分析

保护版与对照版采用相同C测试源码，并在同一QEMU AArch64 MTE虚拟机中运行。保护版包含论文修改版SafeStack和TCMalloc，对照版不包含这两个保护组件。基础功能比较中，保护版40次堆、栈越界全部产生MTE故障，对照版对应的40次越界均未产生MTE故障。完整机制测试中，保护版观察到680次预期MTE故障，对照版未观察到MTE故障；保护版的10组标签轮转测试全部符合周期规律，对照版没有形成相同的标签轮转。

对照版共有400条记录因无法形成边界距离和粒度测试所需的连续布局而被排除，其中包括320条堆边界记录和80条粒度记录。因此，1720条表示保护版和对照版生成的记录总数，并不表示所有记录均完成了有效的一一比较。该结果反映了普通分配布局与StickyTags尺寸分类布局之间的差异，也限制了两种程序在完整机制矩阵中的直接可比性。

此外，当前构建脚本对保护版使用`-O2`和全程序链接优化，对照版使用`-O0`，两种程序除保护组件外还存在编译选项差异。因此，对照结果可以表明MTE故障和标签轮转与StickyTags保护配置相关，但不能作为严格单变量实验，也不能据此计算真实程序中所有空间漏洞的总体检测率。

### 8.4 实验局限性

本实验在QEMU软件模拟的AArch64 MTE环境中完成，能够观察标签行为和故障类型，但不能代表真实Arm设备的运行时间和硬件开销。测试程序主要针对标签轮转、保护边界和标签持久性等机制构造，尚未覆盖大型应用中的复杂分配模式、线程交互和实际漏洞触发路径。

测试实现本身也存在一定限制。机制测试设置MTE模式时未检查`prctl`返回值，但独立环境探针已确认本次运行中的MTE系统调用成功，并且原始日志实际记录到MTE专用故障。基础功能程序没有在每轮运行时验证堆、栈对象的顺序和相邻关系，相关布局主要依据代表性输出确认；机制边界测试则通过地址排序和连续步长检查保证测试前提。持久性测试的每种组合只观察到一个被反复复用的原始地址，因此其结果主要反映固定位置重复使用时的标签稳定性。

论文中的真实设备实验、SPEC CPU2006/2017性能评测、Juliet测试集、8个真实CVE、侧信道实验、x86扩展和时间安全方案未包含在本次实验中。由此，本实验完成的是StickyTags核心标签布局和有限距离空间保护机制的初步复现，而不是对论文全部安全性与性能实验的完整复现。
